# kernel_comp — multi-frontend kernel/model compilation comparison

This tree benchmarks the **same** neural network, compiled through several
different frontend/lowering pipelines, against each other and against a
PyTorch reference. Every pipeline reads the same `float32` weights and input
blobs and writes the same output blob, so differences in the output are
correctness differences and differences in the timing are pipeline
differences — nothing else varies.

Pipelines currently compared (one subdirectory per model, per pipeline):

| Variant          | Source artifact imported          | Produced by                          |
|------------------|-----------------------------------|--------------------------------------|
| `mim_llvm`       | `<Name>_mim.ll` (LLVM IR)         | mim frontend, straight to LLVM IR    |
| `mim_mlir_llvm`  | `<Name>_mim_mlir.mlir` (linalg)   | mim frontend, via MLIR               |
| `mlir_llvm`      | `<Name>_mlir.mlir` (linalg)       | torch-mlir                           |
| `mlir_mim_llvm`  | `<Name>_mlir_mim.mim`             | reserved; no `.ll`, skipped by builds|
| `iree`           | `<Name>.vmfb` + `<Name>.params.txt` | `iree-compile` (external)          |

`mlir_llvm` is the reference variant for all relative-timing plots.

---

## 1. Prerequisites

**LLVM/MLIR — all from the *same* build.** Textual LLVM IR is not stable
across major versions, so `mlir-translate`, `opt`, `llc` and `clang` must
come from one tree:

```
mlir-opt  mlir-translate  opt  llc  clang  llvm-config
```

The generated drivers link against MLIR's C runner utilities, so that build's
`lib/` directory is needed too. It defaults to
`/home/harithf/repos/complete/llvm-project/build/lib` and is overridable:

```bash
export LLVM_LIB_DIR=/path/to/llvm-project/build/lib
```

**Python.** `numpy` for everything; `torch` for the reference forward pass in
`reporter.py`; `matplotlib` for `visualize_timing.py`. The IREE steps
(`gen_vm_driver.py` and `reporter.py --with-iree`) additionally need
`iree.runtime`, and must be run with the interpreter that has it, e.g.
`/home/harithf/Projects/SAAisFP/torch/.venv/bin/python`.

All commands below are run **from the repository root**
(`kernel_comp/`) unless stated otherwise.

## 2. Directory layout

One directory per model, named `NN_ModelName` (two-digit prefix + name). The
prefix is stripped everywhere to form the *model name*: `01_MLP` → `MLP`.
That name is what every generated filename is built from.

```
01_MLP/
├── torch_ref/1_MLP.py            <- PyTorch source: class Model + get_init_inputs()
├── mim_llvm/
│   ├── MLP_mim.ll                <- IMPORTED (mim frontend)
│   └── MLP_driver_mim.c          <- generated by gen_drivers.py
├── mim_mlir_llvm/
│   ├── MLP_mim_mlir.mlir         <- IMPORTED (mim frontend, linalg)
│   ├── MLP_lowered.mlir          <- generated by lower.sh
│   ├── MLP_mim_mlir_llvm.ll      <- generated by lower.sh
│   └── MLP_driver_mlir.c         <- generated by gen_drivers.py
├── mlir_llvm/
│   ├── MLP_mlir.mlir             <- IMPORTED (torch-mlir, linalg)
│   ├── MLP_lowered.mlir          <- generated by lower.sh
│   ├── MLP_mlir_llvm.ll          <- generated by lower.sh
│   └── MLP_driver_mlir.c         <- generated by gen_drivers.py
├── mlir_mim_llvm/MLP_mlir_mim.mim
├── iree/
│   ├── MLP.vmfb                  <- IMPORTED (iree-compile)
│   ├── MLP.params.txt            <- IMPORTED (iree-compile report)
│   ├── MLP.irpa                  <- generated by gen_vm_driver.py
│   ├── MLP_input.bin             <- copy, generated by gen_vm_driver.py
│   └── MLP_driver_iree.py        <- generated by gen_vm_driver.py
├── MLP_weights.bin               <- generated by gen_data.py
├── MLP_input.bin                 <- generated by gen_data.py
├── bin/                          <- generated by compile_all.sh (gitignored)
│   ├── mim_llvm  mim_mlir_llvm  mlir_llvm
├── outputs/                      <- generated by reporter.py (gitignored)
│   ├── output_<variant>.bin
│   └── timing_<variant>_<run_id>.json
└── 01_MLP_<run_id>.json          <- the report, written by reporter.py
```

A directory is recognized as a *model directory* by the presence of
`<Name>_weights.bin`, `<Name>_input.bin` and `bin/`. Nothing hardcodes the
list of variants — whatever executables end up in `bin/` are what gets
compared.

## 3. Step 1 — Import the models

### 3.1 Create the model directory

```bash
mkdir -p 07_MyModel/{torch_ref,mim_llvm,mim_mlir_llvm,mlir_llvm,mlir_mim_llvm,iree}
```


### 3.2 Drop in the artifacts

Copy the frontend outputs into the matching variant directory, and the
original PyTorch definition into `torch_ref/`:

| Put this file …                    | … here                        |
|------------------------------------|-------------------------------|
| mim frontend LLVM IR               | `07_MyModel/mim_llvm/`        |
| mim frontend linalg MLIR           | `07_MyModel/mim_mlir_llvm/`   |
| torch-mlir linalg MLIR             | `07_MyModel/mlir_llvm/`       |
| `iree-compile` `.vmfb` + `.params.txt` | `07_MyModel/iree/`        |
| PyTorch `Model` class (`.py`)      | `07_MyModel/torch_ref/`       |


**Constraints the rest of the pipeline depends on:**

* Exactly **one** source `.mlir` per variant directory. `lower.sh` refuses to
  guess if there are several.
* `mim_llvm/<Name>_mim.ll` must be present for every model — it is the only
  self-contained shape source. MLIR's `convert-func-to-llvm` output erases
  compile-time shapes (every memref becomes `ptr`/`i64`), so `gen_data.py`,
  `gen_drivers.py` and `reporter.py` all recover shapes by parsing the
  raw-pointer `mim` `.ll` and matching parameters positionally.
* `torch_ref/*.py` must define a class `Model`; `get_init_inputs()` is used
  to construct it when present (falling back to a no-arg constructor, then
  `num_classes=`). Without it the report still runs, but uses one compiled
  pipeline as the baseline instead of an independent reference.

## 4. Step 2 — Generate weights and input

```bash
python3 scripts/gen_data.py .                 # every model
python3 scripts/gen_data.py 01_MLP            # one model
python3 scripts/gen_data.py . --seed 42
python3 scripts/gen_data.py . --dry-run
python3 scripts/gen_data.py . --force         # overwrite existing blobs
```

For every `mim_llvm/<Name>_mim.ll` found, the LLVM signature is parsed, the
argument whose leading dimension matches the return value's batch size is
treated as the **input**, and every other argument (weights and biases alike)
as a **weight**. Two raw `float32` blobs land in the *model root*:

```
01_MLP/MLP_weights.bin   all non-input params, concatenated in signature order
01_MLP/MLP_input.bin     the input tensor
```

Signature order is PyTorch's `named_parameters()` order, which is what makes
the same blob usable by the C drivers, the IREE `.irpa`, and the torch
reference.

## 5. Step 3 — Lower the MLIR

```bash
./scripts/lower.sh .                          # whole tree
./scripts/lower.sh 01_MLP                     # one model, both MLIR variants
./scripts/lower.sh 01_MLP/mlir_llvm           # one variant directory
```

The argument is searched **recursively** for any directory that directly
contains a `*.mlir` that is not itself a `*_lowered.mlir`. Directories with no
source `.mlir` (`mim_llvm/`, `mlir_mim_llvm/`, `bin/`, …) are simply not
matched, so passing the whole tree is safe. Each match produces two files:

```
<dir>/<Name>_lowered.mlir      fully lowered to the LLVM dialect
<dir>/<Name>_<variant>.ll      LLVM IR, via mlir-translate
```

### What the default pipeline does

Convolutions get their **output-width iterator interchanged to innermost**,
matmuls get **tiled 32³**. Matching is by op *structure* (rank + a
`mulf`/`addf` contraction body), never by op name — torch-mlir emits named
`linalg.conv_2d_nchw_fchw`, mim emits `linalg.generic` for everything, and
both must be caught. Pooling is deliberately excluded by the same filter.

The interchange keeps the reduction dimensions in their relative order, so
outputs are **bit-identical** to the un-interchanged pipeline. Measured 13.5×
on VGG16 across both frontends. The long comment block at the top of
`lower.sh` documents the measurements, the rejected alternatives, and what is
still left on the table.

### Flags and env vars

| | |
|---|---|
| `--baseline` | the old pipeline (global `--affine-loop-tile` + `--affine-loop-fusion`), kept for A/B only — **do not report numbers from it** |
| `--max` | obsolete; ignored with a warning (it never matched a convolution) |
| `LOWER_SH_DEBUG_PRINT_PASSES=1` | print the exact `mlir-opt` pass list per directory |
| `LOWER_SH_FUSE=1` | add `--linalg-fuse-elementwise-ops`; **measured slower** (1.66× on AlexNet/mim) — off by default |

A full run of this tree is expected to report 16/16 successes. Failures are
per-directory: one bad model does not stop the others, and the script exits
non-zero with a list at the end.

## 6. Step 4 — Generate the drivers

### 6.1 C drivers (all non-IREE variants)

```bash
python3 scripts/gen_drivers.py .              # every .ll under the tree
python3 scripts/gen_drivers.py . --dry-run
python3 scripts/gen_drivers.py . --force      # overwrite existing drivers
```

Run this **after** `lower.sh`, since it works off `.ll` files and the MLIR
variants have none until then. Every `.ll` gets a matching C driver next to
it:

```
mim_llvm/<Name>_driver_mim.c        raw-pointer calling convention
*/<Name>_driver_mlir.c              MLIR's scalarized memref convention
```

Two conventions are handled. The **mim** style passes typed pointers (flat or
as a struct of pointers — the LLVM ABI flattens both), and shapes come
straight from the `.ll`'s own static signature. The **mlir** style expands
every memref into `(alloc ptr, aligned ptr, offset, sizes[R], strides[R])`
with no shapes recoverable from the file; those borrow shapes positionally
from the same model's `mim` `.ll` and compute standard row-major contiguous
strides.

Every generated driver takes the same command line:

```
<driver> <weights.bin> <input.bin> <reps> <output.bin> [run_id] [timing.json]
```

It runs the model `reps` times, writes the output blob, and writes its own
timing JSON (median/mean/min/max in ns) — `reporter.py` passes the path in and
reads it back rather than scraping stdout.

### 6.2 IREE driver (optional)

Must run under a Python that has `iree.runtime`, because writing the `.irpa`
needs it:

```bash
/path/to/venv/bin/python scripts/gen_vm_driver.py .
/path/to/venv/bin/python scripts/gen_vm_driver.py 01_MLP --force
/path/to/venv/bin/python scripts/gen_vm_driver.py . --device local-task
```

For every model that already has `iree/<Name>.vmfb` and
`iree/<Name>.params.txt`, this parses the params file for the entry function,
parameter scope and ordered parameter list, splits `<Name>_weights.bin` into
those parameters as `iree/<Name>.irpa`, copies the input blob in, and writes
`iree/<Name>_driver_iree.py` taking the **same** command line as the C
drivers. Everything it touches stays inside `iree/`, so the IREE experiment is
fully separable from the rest of the tree.

The device defaults to `local-sync` (single threaded) to match every other
pipeline; `--device` changes the baked-in default and `IREE_DEVICE` overrides
it at run time.

## 7. Step 5 — Compile

```bash
./scripts/compile_all.sh                      # scan ./ , -O3, host CPU
./scripts/compile_all.sh . O3 /path/to/llvm-project/build/lib
./scripts/compile_all.sh . -portable          # generic x86-64 (~1.28x slower)
./scripts/compile_all.sh . -no-opt            # old .ll -> llc path, for A/B
```

Each `<model>/<variant>/` holding a `.ll` plus its generated driver `.c` is
built as

```
opt -O3 -mtriple=<host> -mcpu=native  ->  llc -O3 -mcpu=native  ->  clang + driver
```

and the executable is placed in that model's own `bin/` directory, named after
the variant: `01_MLP/bin/mlir_llvm`, `11_VGG16/bin/mim_llvm`, … — right next
to that model's weights and input, so a single directory has everything
needed to run it. Intermediate `.opt.bc` / `.o` files are removed afterwards.
A directory with a `.ll` but no driver `.c` is reported as a failure (run
`gen_drivers.py` first); a directory with no `.ll` at all is skipped silently.

**The `opt` step is not optional.** `llc` is codegen only — LLVM's loop
vectorizer lives in the middle end. The convolutions coming out of `lower.sh`
are shaped precisely so the vectorizer can take them, and skipping `opt`
means nothing ever looks (~11× on a VGG16 conv layer). `opt` also needs the
explicit `-mtriple`: without it there is no TargetMachine, `-mcpu` is silently
ignored, and matmul never vectorizes (4.5× on 512³). Both are handled by the
script; the header comment has the measurements.

`scripts/build_all.sh` is the older variant of this script — `-O2`, no `opt`
step, and it collects binaries into `scripts/bin/<Model>_<variant>` instead of
per-model `bin/`. `reporter.py` looks in the per-model `bin/`, so use
`compile_all.sh`.

## 8. Step 6 — Run and report

```bash
python3 scripts/reporter.py .                            # every model
python3 scripts/reporter.py 01_MLP                       # one model
python3 scripts/reporter.py . --reps 10 --pin-cpu 2 --with-iree
python3 scripts/reporter.py . --timeout 1200 --rtol 1e-3
```

For each model, every executable in `bin/` is run with the shared weights and
input, its output compared against a reference, and one timestamped JSON
report written to the model's own directory:

```
01_MLP/01_MLP_<YYYYmmdd_HHMMSS>.json
```

**Reference**, in order of preference:

1. `torch_ref/*.py` — the `Model` class is loaded, its parameters bound in
   `named_parameters()` order from `<Name>_weights.bin`, and a forward pass
   over `<Name>_input.bin` is ground truth.
2. Otherwise one compiled pipeline is the baseline (`mim_llvm` preferred, as
   the least transformed lowering) — pairwise agreement across pipelines is
   still a meaningful correctness signal.

**Metric.** PASS requires `max|pred-ref| / mean|ref| <= rtol + atol/mean|ref|`,
i.e. error judged against the tensor's own scale. Neither a pure absolute nor
a pointwise-relative tolerance works here: unnormalized random weights push
VGG16's outputs to ~5e24 (no `atol` is meetable) and pointwise `diff/|ref|`
explodes wherever `ref` is near zero. Different lowerings sum in different
orders and are not expected to be bit-identical, only faithful. Defaults are
`--rtol 1e-3` (≈50× margin over the measured fp32 reduction-order floor of
2e-5) and `--atol 1e-2`.

**Options:**

| Flag | Meaning |
|---|---|
| `--reps N` | reps passed to each driver (default 1) |
| `--rtol` / `--atol` | tolerance knobs described above |
| `--pin-cpu 2` | `taskset -c` every run; strongly recommended on hybrid P/E-core machines. Defaults to `$PIN_CPU`, recorded in the report as `pinned_cpu` |
| `--with-iree` | also run `iree/<Name>_driver_iree.py`. Off by default: without it nothing under `iree/` is read or run |
| `--run-id ID` | shared id used in every report and timing filename this run (default: a generated UTC timestamp) |
| `--timeout S` | per-pipeline run timeout (default 600) |
| `--out-dir DIR` | where raw `output_<variant>.bin` goes (default `<model_dir>/outputs`) |
| `--report-dir DIR` | where the JSON report goes (default the model's own directory) |

**Report contents.** Top level: `model_name`, `run_id`, `reference_source`,
`reps`, `pinned_cpu`, `output_shape`, `fastest_pipeline`, `all_pass`, plus a
`timing_summary` giving each variant's `median_ms` and `rel_median` (ratio to
the fastest for that model). Per pipeline, under `pipelines.<variant>`:
`max_abs_diff`, `max_diff_over_scale`, `top1_match`, `status`, and the full
`timing` block from that driver.

Because `--run-id` is shared across models, one run of the whole tree produces
one matching `<model>_<run_id>.json` per model — which is exactly what the
plotting scripts key off.

## 10. Recommended End to end

Adding a new model and getting a report out of it:

```bash
# 1. import
mkdir -p 07_MyModel/{torch_ref,mim_llvm,mim_mlir_llvm,mlir_llvm,iree}
cp .../mimir_graph_*.ll        07_MyModel/mim_llvm/MyModel_mim.ll
cp .../mimir_graph_*.mlir      07_MyModel/mim_mlir_llvm/MyModel_mim_mlir.mlir
cp .../7_MyModel_torch.mlir    07_MyModel/mlir_llvm/MyModel_mlir.ll
cp .../7_MyModel.py            07_MyModel/torch_ref/MyModel.py

# 2. data
python3 scripts/gen_data.py 07_MyModel --seed 42

# 3. lower
./scripts/lower.sh 07_MyModel --max

# 4. drivers
python3 scripts/gen_drivers.py 07_MyModel
/path/to/venv/bin/python scripts/gen_vm_driver.py 07_MyModel

# 5. compile
./scripts/compile_all.sh 07_MyModel O3

# 6. run + report
python3 scripts/reporter.py 07_MyModel --reps 10 --pin-cpu 2 --with-iree

# 7. plot
python3 scripts/timing_to_csv.py --root .
```

Re-running the whole tree after a change to `lower.sh`:

```bash
./scripts/lower.sh . --max && python3 scripts/gen_drivers.py . --force \
  && ./scripts/compile_all.sh . O3 \
  && python3 scripts/reporter.py . --reps 10 --pin-cpu 2 
```

## 11. Notes 

* **Order matters.** `gen_data.py` needs the imported `mim` `.ll`;
  `gen_drivers.py` needs `lower.sh` to have produced the MLIR variants' `.ll`;
  `gen_vm_driver.py` needs `<Name>_weights.bin` to split into an `.irpa`;
  `compile_all.sh` needs the generated `.c`; `reporter.py` needs `bin/`.
* **Regenerate drivers after re-lowering.** `gen_drivers.py` skips existing
  `.c` files unless `--force` is passed, and a changed signature with a stale
  driver is a silent mis-run, not an error.
* **Pin the CPU when timing.** On hybrid P/E-core machines an unpinned run
  can land on an E-core and produce a number that is not comparable to
  anything. `--pin-cpu` / `$PIN_CPU`; the value is recorded in the report.
* **Everything generated is gitignored**: `bin/`, `outputs/`, `*lowered*`,
  `*.ll`-derived objects, `*.o`, `*.so`, `*.a`, `*.bin`. The JSON reports are
  not — they are the results and are meant to be committed.
* **`mlir_mim_llvm/`** holds a `.mim` file only. It has no `.ll`, so
  `lower.sh`, `gen_drivers.py` and `compile_all.sh` all skip it silently. It is
  a placeholder for a pipeline that is not wired up yet.
* **`17_SqueezeNetFireModule/`** is imported but empty apart from
  `torch_ref/` — it has no frontend artifacts yet, so no step below import
  applies to it.
